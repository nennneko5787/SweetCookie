# v8 — 向きのプローブ（**現行**。v1〜v7 の記録は下）

**§4.1.3 の位置は実機で確定した**（画面左・至近・大きさ一致）。残るは**向き**。
本実装は彼女の鞄側を、統合版は顔側を見せる — 差の角度は**目測でしかない**（報告者自身が
「憶測なので信用しないほうがいい」と言っており、そのとおりに扱う）。だから v8 は
**角度そのものを読む**。

## v1〜v7 の教訓を全部入れた

| 教訓 | v8 での対策 |
|---|---|
| バニラアイテム対象は一人称で描かれない（v3/v4） | **BP でカスタムアイテム `lepus:probe` を定義**（`probe_bp/`）。ホシノと同じ経路 |
| UUID・version 据え置きでキャッシュが差し替えを拾わない疑い（v5〜v7） | **UUID を新規に、version を [8,0,0] に** |
| v6 で UV が 16×16 の箱 UV に収まらない cube を作った疑い | 全 cube を `2(w+d) ≤ 16` かつ `h+d ≤ 16` に収めた（v1〜v4 で実績のある範囲） |
| material `enderman` の疑い（v5/v6） | `entity_alphatest`（v4 で実績） |

## 中身

ジオメトリはコーパスと同じ系統（`binding` なし、`root → waist → body → root2 → waist2 →
body2(reset)`）。`body2` の下に、**向きと軸が形で読める** 3 本＋胴体:

| ボーン | 形 | 意味 |
|---|---|---|
| `nose` | **前方（−Z）へ突き出た棒** | **どちらを向いているか** — 本丸 |
| `pillar` | 縦長の柱、**+X 側** | X の符号 |
| `slab` | 横長の板、**−X 側** | X の符号（検算） |
| `body2` | 小さい胴体 | 基準 |

アニメーションは**彼女の `.hand` の実数値そのまま**:
`root2 rotation [0,-85,0] position [-32,-2,-9] scale 1.2`、`hold_on_last_frame`、
条件も同型（`v.main_hand && c.is_first_person`）。

# （旧）一人称の X 軸プローブ — 役目を終えた。結論は SC-180 §4.1.3

**決着: 「座標の矛盾」は矛盾ではなかった。** Mojang の文書の
「vertices are **translated, rotated, then scaled**」は**頂点に適用する順序**で、
position のオフセットは**ボーン自身の回転で回る**。本実装は同じ文を行列の掛け順として
読み、鏡像を実装していた。ホシノの `.hand` は `root2` に回転 −85° と位置 [−32,−2,−9] を
**同時に**書く唯一の重い例で、正しい順序ではオフセットが回って
**[+7.4, −2.4, −39.2] ＝ 画面左・前方 2.5 ブロック・横向き・1.2 倍** — 統合版のフレームと
特徴が全部一致する。

このプローブが出した確定事項（どれも決着に必要だった）:

| | 版 |
|---|---|
| **+X ＝ プレイヤーの左**（画面で確定 ⇒ 探索を軸から合成へ向けた） | v3 |
| 位置チャンネルは効いている | v3 |
| 手持ち／着用の差では説明できない | v3/v4 |
| バニラアイテム対象の attachable は一人称で描かれない（下記） | v3/v4 |

**未解決のまま残すもの:** v5〜v7 は三人称でも描かれなかった。原因は特定していない
（v5/v6 は material `enderman` が疑わしいが、v7 で `entity_alphatest` に戻しても
出なかった — **manifest の UUID と version を全版で据え置いたため、統合版のパック
キャッシュが v7 の差し替えを拾わなかった可能性がある**。次にプローブを作る人は
版ごとに version を上げること）。

**バニラアイテムの件は `attachable/item` 実装時に必ず要る:** 統合版は
`minecraft:stick`（手持ち・v3）にも `minecraft:leather_chestplate`（着用・v4）にも
一人称で attachable を描かなかった。カスタムアイテム（`kivotos:hoshino_onbu`）は描く。
バニラの盾・トライデントが一人称に出るのは `binding` ＋ 専用アニメーション経由。

以下は当時の記録。

**目的: 1 ビットだけ読む。** 統合版で、`body` 派生の attachable のボーンに
アニメーションが `position` の **X を正の値**で書いたとき、**それは画面のどちら側に出るか。**

## なぜこれが要るか

| | |
|---|---|
| Mojang のジオメトリ | `rightArm` が **−X**、`leftArm` が **+X** ⇒ **+X はプレイヤーの左** |
| 一人称はプレイヤーの向きに沿う | ⇒ **+X ＝ 画面の左**（のはず） |
| コーパスの `.hand` | `root2` に **−32**（＝画面の右を指す） |
| 統合版の実際 | 彼女は**画面の左**に出る |

**この 4 つは同時に成り立たない。** そして `body` 派生の attachable が一人称でどう置かれるかは
**どの資料にも書かれていない**（バニラに `body` 派生で一人称に出る attachable が 1 つも無く、
比較対象が存在しない）。キャラクターのモデルで測ると、左右対称・複数アニメーションの合成・
180° 回転が混ざって読めない。**このパックはその全部を取り除いてある。**

## v1 で分かったこと（実機・統合版）

初版は 5 本のボーンを ±8 / ±32 の X だけ動かした。結果:

- **三人称: 頭の上に赤い十字架。** `pillar`（縦棒）と `slab`（横棒）が同じ場所に重なった形。
  `.hand` は `c.is_first_person` 条件なので三人称では再生されない ⇒ **予告どおり**。
  パックも条件分岐も正しく動いている
- **`body` 派生の attachable に −24 の Y オフセットは掛かっていない。** y 32〜46 に書いた
  キューブが身長 32 のプレイヤーの頭上に出た。足元原点のまま
- **一人称: 何も見えない。** ただしこれは**両義的**で、「X で画面外へ飛んだ」のか
  「そもそもカメラの中／後ろにいる」のか区別がつかない

**v2 はその両義性を潰すために、一人称で全部を前方へ押し出す。**

## v2 で分かったこと（実機・統合版）

- **三人称: 3 本が頭上に縦に並んで見える**（立方体・柱・板）＝ **休止姿勢のまま**。予告どおり
- **一人称: 依然として何も見えない**

**v2 でも両義的だった。** 「前方へ動かしたが描かれない」のか「**`.hand` がそもそも再生されて
いない**」のかは、条件付きで再生している限り区別できない。**v3 は条件を外す。**

### v3 の切り分け

`scripts.animate` を `["hand"]`（**無条件**）にした。両視点で再生される。

| 三人称 | 一人称 | 結論 |
|---|---|---|
| 前方（胸の前）に 3 本が出る | **出る** | 座標が読める。X の符号を三人称でも一人称でも直接読む |
| 前方に 3 本が出る | **出ない** | **`body` 派生の attachable は一人称では描かれない**。座標の問題ではない |
| 頭上のまま動かない | — | 位置チャンネルが効いていない。別の問題 |

**2 行目なら、この機能で一番長く開いていた問いが「前提が無かった」で閉じる。**

### 併せて確認すること — 「画面左上のピンクの塊」はペーパードールではないか

統合版のスクリーンショットの**左上隅**には Bedrock のペーパードール HUD があり、
そこに attachable も描かれる。引き継ぎの観測は
「画面**左上**にピンクの塊（髪）。**視点を振っても位置関係は不変**」で、
位置・大きさ・不変性の 3 つともペーパードールの特徴と一致する。

**もしそうなら「統合版は一人称で彼女を画面左に描く」という前提自体が存在せず、
座標の矛盾は最初から矛盾ではない。**

## v3 で確定したこと（実機・統合版）

無条件再生（`"animate": ["hand"]`）にした版。

**① 位置チャンネルは効いている。** 三人称でプローブが頭上から胸の高さへ移動した。

**② +X ＝ プレイヤーの左。画面で裏付けた。** 三人称・正面から見て:

| ボーン | 書かれた X | 見る側から | ⇒ プレイヤーから見て |
|---|---|---|---|
| `slab`（横棒） | **−8** | 左 | **右** |
| `pillar`（縦棒） | **+8** | 右 | **左** |

Mojang のジオメトリ（`leftArm` が +X、`rightArm` が −X）と一致。**もう観測に依存しない。**

**③ 一人称では、無条件でも何も描かれない。** しかし統合版はおんぶホシノを一人称で
（画面左に、近く、大きく）描いている。**差は座標ではない。**

### v4 の仮説 — 手に持つか、着ているか

| | 対象アイテム | |
|---|---|---|
| v1〜v3 のプローブ | `minecraft:stick` | **手に持つ** |
| おんぶホシノ | `kivotos:hoshino_onbu` | **`attachables/kivotos_special_armor/`** ＝ **着る** |

**仮説: 着ている attachable は一人称で描かれ、手に持っている attachable は
（`rightitem`/`leftitem` に `binding` していない限り）描かれない。**
一人称は腕とアイテムボーンのリグしか描かないので、そこに属さない手持ちモデルは落ちる。

v4 は対象を **`minecraft:leather_chestplate`（バニラの防具）** に変えただけ。**着て**確かめる。

**当たっていれば本実装は一人称の担当が丸ごと逆。** いまは手持ちを一人称で描き、
装備品は三人称のレイヤーにしか届いていない（`attachable/first_person` の台帳に
"A worn attachable is not drawn in first person" と明記してある）。

## 中身（100 % 自作。憲章 §10）

コーパスと**同じ構造** — ここが肝心:

- `binding` を使わない（コーパスも 1 箇所も使っていない）
- `root` → `waist` → `body` を自分で宣言し、**同名で装着者のボーンに噛ませる**
- `scripts.animate` は `{"hand": "v.main_hand && c.is_first_person"}`、
  `pre_animation` で `v.main_hand = c.item_slot == 'main_hand';`
- 対象アイテムは `minecraft:stick`（バニラのアイテムなのでビヘイビアパック不要）

`body` の子に、**形で区別できる**ボーンが 3 本。休止姿勢では頭上に縦に並ぶので、
三人称でも 3 つが別々に見える:

| ボーン | 形 | 一人称で書かれる位置 |
|---|---|---|
| `cube_fwd` | **立方体**（2×2×2） | `[0, −8, −20]` ＝ **真正面**。X は動かさない |
| `pillar` | **縦長の柱**（1×6×1） | `[+8, −14, −20]` ＝ 正面 ＋ **X を +8** |
| `slab` | **横長の板**（6×1×1） | `[−8, −20, −20]` ＝ 正面 ＋ **X を −8** |

`−20` は前方（コーパスの `.hand` が `[0,0,−11]` でカメラの 0.69 ブロック前に出ることから、
**−Z が前方**）。Y は 3 本が縦にずれるようにしてあるので、重なって読めなくなることがない。

テクスチャはバニラの赤い羊毛をパス参照するだけ（画像は同梱しない）。
