# 0005 — 計画

## 境界

ブロックと同じ原則: **間違えうる計算は `core` に置き、Minecraft 側は薄くする。**

```
core:  .json           -> AttachableIr / AnimationIr        （解析）
core:  GeometryIr + 時刻 -> ボーンごとの 4x3 行列            （合成。ここが一番間違えやすい）
main:  行列 + GeometryIr -> submitCustomGeometry            （転記）
```

ボーン行列の合成を `core` に置くのが要点。階層の掛け順、pivot まわりの回転、`reset`、
スケール、Bedrock と Java の座標系の差 — 全部ここに閉じ込めれば、クライアントを起動せずに
ミリ秒でテストできる。0002 のミラー問題が「実機で人間が見るまで分からない」状態だったのは、
この層が無かったから。

## 訂正: 差し込み口は 1 つではない（実機で判明）

段階 A・C を動かして分かったこと。**`SpecialModelRenderer` は「手に持つ物」には正しく、
「体に付く物」には誤り**だった。

症状は「モデルが足元に来る」。特殊レンダラは**アイテムの位置**（＝手）を原点に描くが、
Bedrock のジオメトリは**足元が y=0 で頭が y=40 のエンティティ空間**なので、手から
2.5 ブロック分ぶら下がる。数値を調整しても直らない。

**Bedrock はそもそも手を原点に描いていない。** attachable はプレイヤーの骨格に結び付けて
描かれる。定義がエリトラのアニメーションコントローラを借りているのも、アニメーションが
`root3` を動かすことに意味があるのも、それが理由。

| 用途 | 差し込み口 |
|---|---|
| カスタムモデルの剣・道具を手に持つ | `SpecialModelRenderer`（実装済み） |
| 肩車・おんぶ・ヘイロー（体に付く） | **プレイヤーのレンダーレイヤー**（`ElytraLayer` と同じ位置づけ） |

どちらが要るかは attachable 自身からは読み取れない。**判定材料は `scripts.animate` が参照する
アニメーションが動かすボーン**で、プレイヤーの骨格に相当するボーン名（`body`, `rightArm` …）を
動かすものは体に付く。段階 B でここを決める。

段階 C の機構（解析・サンプラー・合成・描画）はこの訂正の影響を受けない。実際、まばたきは
正しく動いている — 位置だけが別の層の問題だった。

## どこに差し込むか（jar を読んで決めた）

**`SpecialModelRenderer`。** 盾・トライデント・チェストが手の中で 3D に見えるのと同じ経路で、
アイテムの表示コンテキストすべてに効く — つまり**一人称と三人称を 1 実装で賄える**。
`extractArgument(ItemStack)` がスタックごとに引数を取り出す形なので、
「1 つの登録で 67 種類のモデル」というキャリアアイテムの設計とそのまま噛み合う。

**ただし、この API は 2 バージョンで割れている。** 今回この単位で初めて見つかった divergence:

| | 1.21.11 | 26.2 |
|---|---|---|
| `submit(...)` | `ItemDisplayContext` **あり** | 無い |
| `Unbaked` | 生型 | `Unbaked<T>` |
| `ID_MAPPER` | `public` | `private`（NeoForge はイベント、Fabric は mixin） |

SC-220 §3 に従い、**薄いラッパだけ**をバージョン別ディレクトリに置く。頂点生成
（`AttachableGeometry`）は共通のままで、4 ノードでコンパイルできることを確認済み。

なお 26.2 が落とした `ItemDisplayContext` は、段階 D の `c.is_first_person` にそのまま要る。
26.2 では別の手段で取る必要がある — 段階 D の最初の課題として記録しておく。

## 判断すること（段階 A で決まる）

**巻き順と UV の向き。** 試作の docstring が自分で「コンパイラでは決まらない」と書いている。
最初の起動で人間が見る。ここで決まれば以降の段階は座標の問題を持ち込まない。

**座標系。** ブロックで確定した「Z ミラー、X は +8 オフセット」は**ブロックの話**で、
エンティティ空間には当てはまらない可能性が高い（Bedrock のエンティティモデルは
ピクセル単位で、原点が足元）。段階 A で 1 回確かめて `spec.md` に書く。
